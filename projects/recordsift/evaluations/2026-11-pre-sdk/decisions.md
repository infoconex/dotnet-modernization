# RecordSift evaluation decisions

The modernization choices below are **proposals**, not approved application changes. The separately listed pilot stakeholder decisions authorize a bounded evaluation process, not production implementation.

| ID | Proposed choice | Disposition | Reason / verification |
|---|---|---|---|
| D-001 | Preserve the verified five-suite test runner; the frozen `main` script historically omitted XLSX. | **Already implemented on RecordSift `release/0.2`, not `main`; no duplicate work authorized** | The previously approved [PR #258](https://github.com/infoconex/RecordSift/pull/258) contains the change. Any branch promotion is a separate release decision. Use the 419/418/0/1 CI acceptance baseline. |
| D-002 | Consider **only** `LangVersion=7.3` as the first minimal root `Directory.Build.props` centralization, with `Condition="'$(LangVersion)' == ''"` to allow project overrides. | **Research recommendation; not authorized for implementation** | All 10 have the identical declaration. [EXP-002](experiments/EXP-002-shared-properties.md) verified Release build, 419 NUnit cases, API/XML and local package parity, while [EXP-005](experiments/EXP-005-sdk-selection-and-overrides.md) verified conditional override behavior. The [property audit](baseline.md) does **not** extend this proof to any other property or Debug parity. No import rewrite. |
| D-003 | Do **not** add a synthetic Directory.Build.targets. | Not recommended currently | The [F-019 source audit](findings.md) found no custom project targets, pre/post-build events or duplicate build tasks across 10 traditional projects. Existing cross-project checks run through CI scripts. Prior [EXP-006](experiments/EXP-006-msbuild-imports.md) proved import feasibility, not business value. Reconsider only if a specific repeated build operation emerges. |
| D-004 | Preserve TargetFrameworkVersion in project files until raw-XML public-API verifier assumptions are removed. | Defer | Avoid false compatibility failures. |
| D-005 | Document an SDK-only Windows build/test or adapted release validation path when operationally useful. | **Optional technical feasibility verified; no implementation authorization** | [EXP-004](experiments/EXP-004-sdk-only-build.md) passes all 419 tests without VS Build Tools; [EXP-009](experiments/EXP-009-sdk-only-release-validation.md) verifies a *temporarily corrected* UTF-8/XML/SDK-Roslyn package/consumer path. Original scripts fail unchanged, and SDK-only negative CS1591 was not executed. Retain current VS-backed release CI unless a documented need justifies change. |
| D-006 | Treat `packages.config` to `PackageReference` as a separately optional migration, not a prerequisite to nor dependent on SDK-style conversion. | **Investigated; defer implementation and central package management** | [EXP-012](experiments/EXP-012-packagereference-isolation.md) verifies exact-pinned PackageReference in traditional net48 with modified tooling and separate NUnit runner installation; full 425-entry original API check fails on 11 source-only records. [EXP-013](experiments/EXP-013-migration-tooling-ci-readiness.md) finds audit/architecture format coupling. Preserve all exact versions initially; conversion is not approved or needed to complete low-risk pre-SDK research. |
| D-007 | Consider `global.json` only when a defined developer/CI **dotnet-toolchain reproducibility** need outweighs SDK installation and update maintenance; do not adopt automatically as a pre-SDK step. | **Optional after verified experiment; not approved for implementation** | [EXP-008](experiments/EXP-008-pinned-sdk-formatter-build.md) proved the existing IDE1006 formatter, Release build, 419 NUnit, XML and 425-entry API checks under exact SDK 10.0.403 and 10.0.303. Existing unpinned CI selected 10.0.403 and passed the formatter/build. Pinning controls `dotnet` SDK choice, not framework targeting or direct Visual Studio `MSBuild.exe`; deciding an update/roll-forward policy remains a separate governance decision. |
| D-008 | Do not modify MSBuild import ordering just to use shared properties. | Reject based on experiment | Early Common.props import produced MSB3107; minimal props centralization passed without it. |
| D-009 | Consider scoped conditional `WarningLevel=4` centralization only if coordinated warning-policy maintenance is worth the added configuration logic. | **Optional, technically verified in EXP-010; low value, not approved** | [EXP-010](experiments/EXP-010-warninglevel-centralization.md) tested all 20 Debug/Release occurrences, override behavior and full relevant gates. The existing C# compiler default is already level 4; a global unconditional property changes `Custom` evaluated behavior, so preserve scope if ever implemented. |
| D-010 | Retain configuration defaults, conditional compiler/output settings, project/assembly identity, resource names, `TargetFrameworkVersion`, production-only XML/CS1591 policy and test flags in their original projects for now. | **Recommend no movement** | Import timing and existing API/package/consumer path assumptions make wholesale centralization unsafe or unnecessary; no experiment has validated moving these settings. See [property inventory](baseline.md). |
| D-011 | Keep dependency format conversion distinct from package simplification or version upgrades. | **Recommend separate decisions; no application change authorized** | [EXP-012](experiments/EXP-012-packagereference-isolation.md) demonstrated **four actual transitive dependency downgrades** after removing nine apparent transitive references even while 419 NUnit tests and 414 compiled API entries passed. Do not treat tests alone as proof of version equivalence. |
| D-012 | When PackageReference migration is separately authorized, keep existing working NuGet CLI restore and IDE1006 formatter and adapt only format-dependent verification and runner provisioning. | **Conditional future recommendation; not authorized** | [EXP-013](experiments/EXP-013-migration-tooling-ci-readiness.md) verified unchanged NuGet restore, formatter, 17/17 candidate pin audit, and XLSX guard positive/negative control; unchanged `packages.config` audit, 425-entry checker and runner location remain incompatible. GUI Visual Studio migration wizard was not executed. |
