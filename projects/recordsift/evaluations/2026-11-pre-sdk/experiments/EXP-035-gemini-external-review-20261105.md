### Additional relevant independent finding

Roslyn's [EditAndContinue managed PDB logic](https://sourceroslyn.io/Microsoft.CodeAnalysis.Features/EditAndContinue/EditAndContinueMethodDebugInfoReader.cs.html) deliberately checks full exact document path because the native managed reader can match partial filenames; a future validator **must not** rely solely on filenames/basenames. The EXP-035 Python comparator currently keys records by basename because the DIA probe redacts paths. Its synthetic controls are useful but cannot substitute for full managed-document path identity or all-document inventory.

### Security prerequisites before the first reader call

1. Inspect actual Windows runner OS image and .NET Framework update inventory including September 2026 and later applicable servicing; **do not infer patch compliance merely from a date or Authenticode**.
2. Inspect COM registration and in-process server identity, the exact DLL loaded (vs a packaged DLL), bitness, file version, SHA-256 and signature; confirm Microsoft's relevant KB/CVE coverage and preflight failure handling. Preserve redacted metadata only.
3. Validate the supported interface revision of the installed COM reader and the availability of Microsoft header/interface declarations and a valid PE metadata importer. Do not mislabel the supplied snippet as runnable C++.

Only if safety/activation prerequisites are established, create a **new isolated experimental scope** using a known-good classic managed PDB fixture, invalid-PDB failure controls, wrong DLL/PDB and checksum corruption controls, then query actual owned and generated documents by full path/algorithm/bytes and compare with exact compiler-input physical bytes (including encoding/CRLF). Do not process untrusted PDBs.
5. Preserve the frozen RecordSift SHA and full historical 425 API/419 NUnit (418/0/1)/five XML/unpublished package/clean net48 consumer gates. Never alter packages, publish, merge, or adopt Source Link based on source inspection alone.
