### F-01 — BLOCKER — Production authorization manifest and approval are not an enforced input

**Perspective:** governance, architecture, security. **Classification:** OBSERVED missing production control; *not* an experimental code bug. **Evidence:** `R:tooling/validators/gate_cn_live_provenance.py:L69-L111` accepts exactly `authorization: DESIGN_VALIDATION_ONLY`, an application SHA and *internally supplied per-component counts*. `R:tooling/pilots/gate-cn/EXP-044/run.ps1:L85-L103` creates that manifest **during** the run. The actual source of authority is described as *prospective*, not implemented, at `R:methodology/acceptance-gates/gate-cn-manifest-custody-review-protocol-20261106.md:L4-L26`.

**Risk:** a writer of the build/review inputs could choose a valid but incomplete component list or alter approved origin/count expectations; the live adapter would have no independently protected release universe to compare against. It is expressly designed not to authorize release, so **this does not discredit the 2/2 fixture evidence**. **Negative control:** create a trusted disposable 2-project build but pass a one-project research manifest: the adapter can legitimately verify *the declared one*; a future production aggregator must reject the missing preapproved project. Verify a one-bit modified manifest fails an independent approval-hash check. **Correction:** implement signed/protected *pre-build* manifest with exact complete component/project/TFM/configuration, source-origin policy, candidate outputs, original gates, policy revision and reviewer identity; store hash outside candidate control; add explicit distinct release-stage executor. **CN:** 01, 08, 10, 11. **Timing:** before future release acceptance; protocol and gap must be visible to humans **now** (not a prerequisite to begin their review).

## Five independent engineering perspectives

**1. Architecture/reusability.** The core independent primitives are relatively clear: `read_msf`/native enumeration; physical snapshot/native hash joining; structured Csc-input comparison; producer verification; and a final per-component research adapter. These are better-separated than a single opaque CI shell test. Yet the application/moniker support contract, expected files and one event layout remain coupled to the EXP-041/042 probe and traditional MSBuild; generalized clean/hexagonal architecture and dependency inversion are not yet demonstrated. See **F-01, F-06, F-07**. A portable *narrow* API is credible, a general .NET framework migration acceptance gate is not.

**2. Build/compiler correctness.** The code uses real byte snapshots before CoreCompile (`R:tooling/pilots/recordsift/EXP-041/CompilerInputSnapshot.targets:L20-L54`) and postcompile byte verification (`L55-L91`, plus live adapter post-check), compares actual structured Csc source identities to capture (`R:tooling/validators/exp042_source_provenance.py:L157-L215`), pairs PE CodeView GUID+age with PDB, independently enumerates named injected/DBI/C13/line keys and includes nonline documents; its `NONE` C13 records are *not* used as cryptographic digests. EXP-043 builds four extra candidate PDBs with `/t:Rebuild`, and the remaining CSV is supplied by EXP-024. Critical unproven expansions concern exact compiler event/output freshness, toolchain pins, hash policy, and parallel event correlation (**F-03/04/07/08**). There is no evidence here that these cases failed historically.

**3. Security/privacy.** The risk model explicitly trusts runner/compiler and locally built PDBs. Parsing bounded PDB data in Python is not a secure sandbox for hostile inputs, and the protocol correctly excludes malicious symbol files. There are real defensive signs: max sizes, path containment, collision checks, private raw bytes outside source tree, fixed error categories, action SHA pins, selected NuGet SHA256 pins and unconditional private-root cleanup. Production must add independent scope signoff, immutable artifact custody and toolchain/advisory proof; public logs and partial failure artifacts require scrutiny (**F-01/03/10/11**). I found no verified private-source disclosure or hostile-PDB exploit.

**4. Quality/test reliability.** The five-suite invocation is real in the harness: 419 tests with 418 passed/1 expected skip are **reported**; historic API baseline claims 425 entries, with five XML outputs, unpublished package and actual clean standalone net48 consumer execution.
